# Лабораторна робота №17: Обробка IO/мережевих помилок та патерн Retry.
**Курс:** Об'єктно-орієнтоване програмування  
**Навчальний заклад:** Рівненський фаховий коледж інформаційних технологій  
**Варіант:** 7 (Отримання списку користувачів)  

---

## Опис реалізованих класів
- **`FileProcessor`**: містить метод `List<string> LoadUsernames(string path)`, який імітує виникнення `IOException` під час перших 3 спроб читання файлу, а на 4-й спробі повертає список користувачів. Для порожнього шляху викидає `ArgumentException`.
- **`NetworkClient`**: містить метод `List<string> GetUsersFromApi(string url)`, який імітує виникнення `HttpRequestException` під час перших 2 запитів до API, а на 3-й спробі повертає список користувачів.
- **`RetryHelper`**: статичний узагальнений клас із методом `ExecuteWithRetry<T>`, що виконує операцію з підтримкою повторних спроб, експоненційної затримки (`initialDelay * 2^(attempt - 1)`), логування кожної невдачі та перевірки винятку через делегат `shouldRetry`.

Висновок
У роботі реалізовано патерн Retry з експоненційною затримкою за формулою initialDelay * 2^(attempt - 1), завдяки чому час очікування між спробами зростає вдвічі (200 мс, 400 мс, 800 мс). Це дозволяє уникнути перевантаження файлової системи чи віддаленого сервера під час тимчасових збоїв, а делегат shouldRetry гарантує, що програма не витрачає час на повтор критичних помилок (наприклад, ArgumentException).

Відповіді на контрольні запитання
Які типи винятків найчастіше виникають при роботі з файлами та мережею?

Для файлів/вводу-виводу: IOException, FileNotFoundException, DirectoryNotFoundException, UnauthorizedAccessException.

Для мережі: HttpRequestException, SocketException, TimeoutException.

Принцип роботи патерну Retry та коли його доцільно використовувати:

Патерн полягає у автоматичному повторному виконанні операції, яка завершилася тимчасовою (транзієнтною) помилкою. Його доцільно використовувати при короткочасних втратах мережі, блокуванні файлу іншим процесом або тимчасовій недоступності API.

Як реалізувати експоненційну затримку між повторними спробами?

Початковий інтервал очікування множиться на степінь двійки залежно від номера поточної спроби: initialDelay * Math.Pow(2, attempt - 1).

Для чого потрібен делегат shouldRetry у класі RetryHelper?

Він дозволяє фільтрувати винятки та повторювати операцію лише для тимчасових помилок (IOException, HttpRequestException), одразу прокидаючи критичні помилки логіки чи валідації (наприклад, ArgumentException).
