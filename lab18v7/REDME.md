# Лабораторна робота №18: Власні винятки та патерн Result.
**Курс:** Об'єктно-орієнтоване програмування  
**Навчальний заклад:** Рівненський фаховий коледж інформаційних технологій  
**Варіант:** 7 (Управління проектами)  

---

## Опис реалізованих класів
- **`ProjectNotFoundException`**: власний клас винятку, успадкований від `System.Exception`, зі властивістю `ProjectId` та набором стандартних конструкторів.
- **`Result<T>`**: узагальнений клас для інкапсуляції результату операції з властивостями `IsSuccess`, `Value`, `Error`, приватним конструктором та фабричними методами `Success(T value)`, `Failure(string error)` і `Failure(Exception ex)`.
- **`ProjectService`**: сервіс управління проектами з двома підходами до обробки помилок:
  - `Project GetProject(int projectId)` — викидає `ProjectNotFoundException`, якщо проект не знайдено.
  - `Result<bool> AssignTask(int projectId, int taskId)` — повертає `Result<bool>.Success(true)` або `Result<bool>.Failure(...)`, якщо завдання вже призначене чи вхідні дані некоректні.

Висновок
Для методу GetProject доцільно використовувати власний виняток ProjectNotFoundException, оскільки відсутність запитуваного об'єкта порушує контракт методу, який зобов'язаний повернути валідний екземпляр Project. Для методу AssignTask краще підходить патерн Result<bool>, адже повторне призначення вже закріпленого завдання є очікуваним бізнес-сценарієм валідації, який не потребує витрат ресурсів на розкручування стеку винятків.

Відповіді на контрольні запитання
Навіщо створювати власні типи винятків? Які переваги це дає?

Власні винятки дозволяють точно ідентифікувати специфічні для предметної області помилки, передавати додатковий контекст (наприклад, ProjectId) та обробляти їх окремо у блоках catch.

Які стандартні конструктори рекомендується реалізовувати для власних винятків?

Конструктор за замовчуванням, конструктор із повідомленням (string message), конструктор із повідомленням та внутрішнім винятком (string message, Exception innerException), а також спеціалізовані конструктори зі своїми властивостями.

Поясніть патерн Result. У яких випадках його використання є більш доцільним, ніж викидання винятків?

Патерн Result<T> повертає об'єкт-обгортку, що містить або успішне значення, або опис помилки. Його доцільно використовувати для передбачуваних сценаріїв відмови (валідація, бізнес-правила, дублікати), де помилка є частиною звичайного потоку роботи програми.

Які сценарії краще обробляти через винятки, а які через патерн Result?

Через винятки — виняткові ситуації, помилки інфраструктури (відсутність файлу, збій мережі) або порушення інваріантів. Через Result<T> — очікувані помилки бізнес-логіки та введення користувача.
