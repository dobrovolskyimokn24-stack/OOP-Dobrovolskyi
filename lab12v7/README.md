# Лабораторна робота №12 (Варіант 7)
**Тема:** Узагальнені типи (Generics). IRepository з where-обмеженнями та тестами.

## Опис структури
- **`IEntity`**: Базовий інтерфейс для сутностей з властивістю `int Id { get; set; }`.
- **`Department`**: Сутність варіанта 7 (`Name`, `Location`), що реалізує `IEntity`.
- **`IRepository<T>`**: Узагальнений інтерфейс репозиторію з обмеженням `where T : class, IEntity`, який оголошує CRUD-операції (`GetById`, `GetAll`, `Add`, `Update`, `Delete`).
- **`InMemoryRepository<T>`**: Реалізація `IRepository<T>` для зберігання даних у пам'яті (`List<T>`).
- **`lab12v7.Tests`**: xUnit-проєкт з 9 юніт-тестами, що повністю покривають усі CRUD-операції та обробку виняткових ситуацій (дублікат ID, відсутній ID).

## Відповіді на контрольні запитання

### 1. Яка роль where-обмежень у Generics? Наведіть приклади їх використання.
Обмеження (`where`) звужують типи, які можна передавати як параметр узагальненого класу або методу. Це дозволяє безпечно використовувати властивості та методи відповідних типів або інтерфейсів без необхідності явного приведення.
- **Приклади:**
  - `where T : class` — тип має бути посилальним.
  - `where T : new()` — тип повинен мати публічний конструктор без параметрів.
  - `where T : IEntity` — тип повинен реалізовувати інтерфейс `IEntity`.

### 2. Навіщо потрібен шаблон IRepository? Які переваги він дає?
Шаблон `IRepository` відокремлює логіку роботи з даними від бізнес-логіки додатка.
- **Переваги:**
  - Єдиний уніфікований інтерфейс для роботи з даними.
  - Легкість підміни джерела даних (наприклад, замінити `InMemoryRepository` на SQL Database без зміни бізнес-логіки).
  - Покращена тестованість коду (простіше писати Unit-тести з використанням заглушок/моків).

### 3. Поясніть, чому юніт-тести є важливими при розробці узагальнених компонентів.
Оскільки узагальнені компоненти спроектовані для роботи з найрізноманітнішими типами даних, юніт-тести гарантують, що загальний алгоритм працює стабільно і передбачувано (включаючи правильну обробку помилок та крайових випадків) незалежно від конкретної сутності.

### 4. Які проблеми вирішують Generics порівняно з використанням object?
- **Строга типізація (Type Safety):** помилки виявляються ще на етапі компіляції, а не під час виконання (`runtime`).
- **Продуктивність:** відсутність операцій пакування/розпакування (`boxing/unboxing`) при роботі зі значущими типами.
- **Чистота коду:** відсутня потреба постійно робити явні приведення типів на кшталт `(Department)obj`.
